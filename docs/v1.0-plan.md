## 1. V0.5 → V1.0 비전

### V0.5 (마무리 — 2026-05-29)
- "한 시즌이 재미있게 진행" — 매치 시뮬 / 사기 / 트레잇 / 시설 / 시즌 시상 작동.
- 단점: UX 자유도 침해 (강제 씬 전환), UI 폴리시 부족, 매치 디테일 단순, 일부 씬 미완.

### V1.0 목표 단어
> **"UX 가 매끄럽고 (인박스 / 자유도 / 시각화), 매치가 자세하고 (신체 / 멘탈 / 옵션), 시장이 정교하다 (협상 / 컵 / 자동 저장)."**

### 비전 vs V0.5 차이 한 줄
- V0.5: "이벤트 발생하면 강제로 그 화면에 던져진다."
- V1.0: "이벤트는 피드에 쌓인다. 사용자가 골라서 처리한다. 기한 있는 것만 추궁한다."

## 3. 범주별 명세

### 3.1 UX 패러다임 — Dashboard 인박스 / 자유도 (사용자 피드백 2.1)

**V0.5 동작:**
- 특정 이벤트 (유스 인스펙션 / 매치 / 보드 약속 / CounterOffer / Happiness < 20 TransferRequest / 1군 콜업) 발생 시 강제 씬 전환 또는 자동 패널 노출.
- 사용자가 "이벤트를 처리하지 않으면 진행 불가" 같은 압박.

**V1.0 변경:**
- **FM 식 피드 / 인박스 패러다임** — 이벤트 = 알림만 누적. 사용자가 클릭해 확인 / 처리.
- 강제 처리 (씬 강제 전환 / 모달 잠금) 항목 = **기한 있는 결정만** (예: CounterOffer 7일 응답 / 보드 약속 시즌 시작 즉시 수락/거절).
- 기한 없는 항목 (Promise 일반 진행 / 어워드 알림 / 사기 변동 / 1군 콜업 권장) = 인박스 누적, 사용자가 골라 처리.
- **Dashboard 인박스 확장**: 카테고리 탭 (전체 / 매치 / 이적 / 사기 / 보드 / 유스), 읽음/안읽음 표시, 만료 임박 강조.

**영향 범위:**
- `DashboardController.OnContinueClicked` — CounterOffer 자동 라우팅 제거 (인박스 알림으로 대체)
- `Inbox` 도메인 신규 또는 기존 in-memory inbox 확장 + 카테고리 / 기한 / 우선순위 필드
- `EventBus` 모든 UI-routing 이벤트 → InboxItem 변환 미들웨어
- `data-flows.md` Dashboard 진입 시퀀스 갱신

### 3.2 Player Profile + Stats UI (사용자 피드백 2.2)

**V0.5 동작:**
- PlayerProfile = 스크롤 형식. Stats 49 필드 동일 색상. 신체 조건 미반영.

**V1.0 변경:**
- **한 화면 레이아웃** — 4 카테고리 (Technical / Mental / Physical / Goalkeeping) 2×2 또는 4-column 그리드. 49 필드 한 눈에.
- **색상 코딩** — stat 값 기준 5단계 색상 (외부화 임계치):
  - 80+ 진녹색 (Elite)
  - 65-79 녹색 (Good)
  - 50-64 회색 (Average)
  - 35-49 주황 (Weak)
  - 34- 빨강 (Poor)
- **신체 조건 표시** — 키 (cm) / 몸무게 (kg) / 우세 발 / 약발 정도. PlayerInfo / Player.physical 신규 필드.
- **§3.17 신체 조건 → 경기 영향** 연동.

**영향 범위:**
- `PlayerProfileController` 전면 재작업
- `Player.physical: PhysicalAttributes` 신규 (height / weight / preferredFoot / weakFootAbility)
- `PlayerGenerator` 신체 조건 추첨 (포지션별 평균 + 편차)
- `MatchSimulator` 일부 이벤트 (헤더 / 민첩성 / 속도) 분기 추가

### 3.5 Transfer 검색 (사용자 피드백 2.5)

**V0.5 동작:**
- 인라인 필터 (포지션 / CA 범위 / 연령 / 국적 / 트레잇 / 시장가 / 계약 잔여). CA 검색 가능 → 스카우트 시스템 모순.

**V1.0 변경:**
- **CA 필터 폐기** — 스카우트 시스템 (정확도 차등) 과 모순. 자기 구단 선수는 정확 표시되지만 검색 필터로는 X.
- **세부 stats 필터** — "Pace ≥ 75", "Finishing ≥ 70" 등. 단 Not-Scouted 선수는 검색 결과 = 정성적 라벨만 표시 (정확 수치 노출 X 유지).
- **주급 필터** — 주급 범위.
- **필터 패널 UI 분리**:
  - Transfer 화면 = 검색창 + [필터] 버튼 + 결과 listing
  - [필터] 클릭 → 패널 슬라이드/모달 → 모든 옵션 (포지션 / 나이 / 국적 / 트레잇 / 세부 stats / 주급 / 시장가 / 계약 잔여 / 스카우트 여부)
  - [적용] → 패널 닫힘 + listing 갱신

**영향 범위:**
- `TransferController` UI 재작업 (필터 패널 분리)
- `TransferSearchFilter` 도메인 확장 (statThresholds: Dictionary / wageRange: (min,max))
- Not-Scouted 선수 검색 결과 라벨링 (`ScoutingVisibility` 활용)

### 3.6 Match Simulation 디테일 (사용자 피드백 2.13)

**V0.5 동작:**
- 5-Zone Markov + 49 stat / 이벤트 종류 (Shot / Pass / Tackle / Foul / Card / Injury / Sub / Cross / Save). 텍스트 이벤트는 일부.

**V1.0 변경:**
- **이벤트 종류 확장**:
  - 패스 (성공/실패) — 점유율 통계만 → 텍스트 표시
  - 턴오버 (Interception / BallLost)
  - 스로인 (LongThrow 외 일반)
  - 프리킥 (Direct / Indirect)
  - 코너킥 (이미 SetPieceResolver — 텍스트 강화)
  - 오프사이드
  - 골키퍼 펀칭 (Punching) / 캐치 (Catch)
- **신체 조건 / 멘탈리티 반영 (§3.17)**:
  - 헤더 이벤트 → 키 / 점프 + jumpingReach
  - 민첩성 → 키 작을수록 보너스
  - 속도 (스프린트) → pace + 약발 정도
  - 빅매치 / 페널티 → pressureHandling (Hidden) + composure
- **선수 조합 시너지** — 빅앤스몰 (큰 ST + 키 작은 윙) / 윙+타겟포워드 / 빠른 윙+크로스 등 조합이 팀 strength 보너스. `TacticImpact` 확장.
