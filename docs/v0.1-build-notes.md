# FM-Lite V0.1 빌드 노트

> **빌드 일자:** 2026-05-22
> **컨셉:** FM의 육성 부분만 떼어내서 시간 압축한 컴팩트 매니저 게임 — 한 시즌 2~3시간 완주.
> **목적:** 한 시즌이 끝까지 진행되는 최소 게임 루프 검증.

---

## 1. 구현된 기능

### 1.1 게임 진행 루프
- 메인 메뉴 → New Game (시드 입력 / 자동) 또는 Load Game (슬롯 리스트)
- 구단 선택 (명성 내림차순)
- 스타팅 스쿼드 가챠 (4라인 5단계 티어 + ACE 마커, 리롤 최대 3회)
- Dashboard (날짜 / 다음 경기 / 리롤 토큰 표시) — [Continue] 로 다음 정지 이벤트까지 자동 진행
- 시즌 종료 (5/15) → 회계연도 (6/1) → 새 시즌 매치 개막 (8/15) 자동 사이클

### 1.2 도메인 시스템
| 시스템 | 핵심 동작 |
| --- | --- |
| **PlayerGenerator** | 명성 기반 CA 분포 + 포지션별 키 스탯 가중치 + 트레잇 부여 + 이름·국적·계약 |
| **ClubGenerator** | 4티어 명성 (Top4 / Euro / Mid / Rel) + 20구단 + 25명/구단 (4-4-2 분배표) |
| **ScheduleGenerator** | Berger 더블 라운드 로빈 (n팀 → n(n-1) 매치) |
| **MatchSimulator** | 시드 고정 + 단순 CA 합 + Poisson 골수 + 라인 가중 득점자 (V0.1 임시 모델) |
| **MatchPostProcessor** | 결과 기록 + 리그 순위 갱신 (승 3 / 무 1 / 패 0) + 피로 +30 starting11 |
| **BackgroundSimulator** | 비활성 구단 매치 일괄 처리 (V0.1 동일 알고리즘) |
| **YouthSystem** | 메인 6/15 + 보조 1/15 인스펙션, 스타 픽 5%, 시드 = newgame ^ date.Ticks ^ userActionHash ^ club.id ^ intake.id ^ rerollsUsed |
| **TransferSystem** | Market Value 6요소 (CA pow 4 + PA gap + age + contract + position + injury) + 상시 검색·오퍼 + 활성화 기간 (6/1~8/31 / 1/1~1/31) 자동 체결 |
| **FacilitySystem** | Scout / Training / Youth 업그레이드 진행 + 완료일 도래 시 적용 |
| **SeasonEndProcessor / NewSeasonProcessor** | FA 전환 + 33+ 확률 은퇴 + 토큰 +3 (cap 5) + fatigue·form 리셋 + 새 일정 |

### 1.3 UI 화면 (11개 씬)
- **MainMenu** — 시드 입력 / 슬롯 리스트
- **ClubSelect** — 명성 내림차순 + 선택 확인
- **Gacha** — 4라인 티어 (Elite / Strong / Average / Weak / Poor) + ACE + 리롤
- **Dashboard** — 날짜·다음 경기·토큰·[Continue]·사이드 메뉴 (스쿼드/유스/이적/일정/순위/시설) + [저장] + [메인 메뉴]
- **Squad / PlayerProfile** — 1군·유스 탭, 능력치 5단계 티어 (스탯 1-20 절대 컷오프) + 트레잇 + 계약 + 시즌별 커리어
- **Youth** — 후보 목록 + 토글 선택 + 리롤 + 영입 확정
- **Transfer** — 포지션·CA 범위 필터 + 결과 목록 + 오퍼 패널 + 활성 오퍼 + 이적시장 열림/닫힘 상태
- **Schedule** — 유저 구단 시즌 일정 (완료 스코어 / 미완료 시간 / 유저 매치 강조)
- **Standings** — 승점·골득실·득점 내림차순 + 유저 행 강조 + `MatchFinishedEvent` 구독 실시간 갱신
- **Facility** — 등급 표시 + 업그레이드 발주 (비용·완료일)

### 1.4 디버그 도구
- **DebugWindow** (Unity 메뉴 `FM-Lite > Debug Window`, Play Mode 전용) — 시간 강제 진행 (1일·1주·1개월) / 자금 추가 / 리롤 토큰 / 부상 강제·회복 / `isDebugMode` 토글
- **isDebugMode** ON 시 `PlayerProfile` 에 CA / PA 정확 수치 노출

### 1.5 직렬화 / 세이브
- `SaveSystem` — Newtonsoft.Json, atomic write (.tmp + File.Replace), 슬롯 폴더 = `state.json` + `meta.json`
- Dashboard 의 [저장] → 슬롯 리스트 패널 → 기존 슬롯 클릭 = 덮어쓰기 / "신규" = `slot_<userClubName>_<yyMMdd_HHmm>` 자동 생성
- Load Game → BuildIndexes 자동 호출 → 같은 시드·같은 행동 = 같은 결과 보장

### 1.6 통합 테스트 (`IntegrationTests.cs`)
- T1 / T1b — 한 시즌 완주 (4팀 리그 365일 진행)
- T2 / T2b — 세이브 일관성 (60일 저장 → 로드 → 30일 진행 = 원본 동일)
- T3 / T3b — 시드 결정성 (같은 시드 두 게임 100일 후 standings 완전 동일)

## 2. V0.1 임시 처리 / 제한사항

> "V0.1 단순화 + V1.0+ 트리거" 정책. `docs/design-decisions.md` 의 V1.0+ 보완 포인트 참조.

### 경기 시뮬레이션
- **분 단위 이벤트 시퀀스 미구현** (`#34`) — V0.1 은 결과 우선 모델 (스코어 + 득점자만). 텍스트 이벤트 / 평점 / 부상 / 카드 V1.0+.
- **strengthExponent k=1.5 임시 변통** (`#33` 보강) — 단순 선형 ratio 의 결정력 부족 보강용. V1.0+ 매치 엔진 재작성 시 폐기 예정.
- **starting11 자동 선정** — top-11 by CA. 라인업 결정 UI / 포지션 무시. V1.0+ 유저 수동 라인업.
- **비활성 구단 동일 알고리즘** (옵션 A) — V1.0+ `publishEvent` 옵션 + 경량 시뮬 분리 트리거.

### 선수 / 능력치
- **CA-Stats 분리 운영** (`#24`) — 매치는 CA 합만 사용, 개별 stats 무관. V1.0+ 매치가 stats 직접 참조 시 derived CA 모델.
- **폼 / 사기 / morale 미구현** (`#30`) — 평점 시스템 부재로 V1.0+ 묶음 도입.

### 이적
- **단일 라운드 AI 응답** (`#37`) — Accept / Reject 만. 역제안 / 다중 협상 / 선수 협상 V1.0+.
- **AI 구단 능동 영입 X** — 사용자 클럽만 오퍼 제출. V1.0+ `CpuTransferAi`.
- **스카우트 정확도 100%** — V1.0+ `Club.facilities.scoutLevel` 기반 PA 추정치 / 트레잇 노출.

### 유스
- **시설 통합 등급** (`#35`) — Youth 시설 1개로 시설+코치+모집 책임. V1.0+ `youthCoachLevel` / `youthRecruitmentLevel` 분리.
- **미영입 후보 즉시 제거** — V1.0+ `youthRejectedToOtherClubRatio` AI 영입.

### 시즌 사이클
- **3 시점 고정 (5/15 / 6/1 / 8/15)** (`#38`) — V1.0+ 캘린더 / 요일 동적 계산 ("5월 마지막 토요일").
- **시상 / 보드 평가 / 재정 결산 / Match 압축 미구현** — 모두 V1.0+ 별도 시스템과 짝.
- **단일 리그** — V0.1 EPL 모티브 20구단. 승강 / 다중 리그 V1.0+.

### 기타
- **단일 포메이션 4-4-2** (`#32`) — V1.0+ `FormationSO` 추출 + 가챠 시 포메이션 랜덤화.
- **컵 / 챔피언스리그 / 국가대표 / 기자회견 / 코치 인사 미구현** — `project-context.md` Out of Scope.

## 3. 플레이에 필요한 정보

### 3.1 시작하기
1. 메인 메뉴 → **New Game**
2. 시드 입력 (선택) — 같은 시드 = 같은 초기 스쿼드. 빈 칸 = 자동 랜덤.
3. 구단 선택 — 명성 내림차순. 빅클럽일수록 시작 스쿼드 강함, 단 명성 대비 평가라 약체로 시작해도 "우리 공격진 훌륭함" 같은 만족감 가능 (`#15`).
4. 스타팅 가챠 — 4라인 티어 평가 마음에 안 들면 [리롤] (최대 3회). [확정] → Dashboard.

### 3.2 진행
- **[Continue]** — 다음 정지 이벤트까지 자동 진행 (유저 매치 / 유스 인스펙션일 / 시즌 종료 등).
- **사이드 메뉴** — 스쿼드 / 유스 / 이적 / 일정 / 순위 / 시설 화면 전환.
- **저장** — [저장] 버튼 → 슬롯 리스트 패널 → 기존 슬롯 클릭 (덮어쓰기) 또는 [신규] 버튼 (자동 슬롯명).
- **메인 메뉴 복귀** — [메인 메뉴] 버튼. 저장 안 한 진행 손실되니 주의.

### 3.3 핵심 메커닉
- **리롤 토큰** — 시즌 시작 +3 (이월 최대 5). 유스 인스펙션 풀 재추첨에 사용 (`#16`).
- **이적시장 vs 활성화 기간** — 검색·오퍼·협상은 상시. 체결만 6/1~8/31 (여름) + 1/1~1/31 (겨울). 시즌 중간에 협상 합의해두면 활성화 기간 진입 시 자동 체결.
- **유스 인스펙션** — 메인 6/15 + 보조 1/15. 시설 등급 ↑ = 평균 PA ↑ + 풀 사이즈 ↑. 스타 픽 5% 확률 PA 평균 +50.

### 3.4 디버그 도구
- Unity 에디터 메뉴 **`FM-Lite > Debug Window`** (Play Mode 만 열림).
- `isDebugMode` 토글 → 선수 프로필에 CA / PA 정확 수치 표시.

### 3.5 세이브 파일 위치
| 환경 | 경로 |
| --- | --- |
| 에디터 | `%USERPROFILE%\AppData\LocalLow\<Company>\<Product>\saves\` |
| 빌드 | 같은 경로 (Company / Product 이름이 같으면 공유, 다르면 분리) |

각 슬롯 = 폴더 (`state.json` + `meta.json`). 폴더 통째로 백업 / 이동 가능.

### 3.6 알려진 함정
- **에디터 슬롯 ≠ 빌드 슬롯** — Product Name 다르면 서로 안 보임. 빌드에서 처음 New Game 한 번 돌려야 슬롯 폴더 생성.
- **외부 시드 마이닝 차단** — 유스 풀 시드에 `currentDate.Ticks + userActionHash` 결합 (`#35`). newgame seed 단독으로 미래 풀 예측 불가.
- **빅클럽 시작 = 의도적 쉬움** — `#15` 명성 대비 상대평가. 빅클럽의 "평범" ≈ 중위권의 "훌륭".

| 항목 | 값 |
| --- | --- |
